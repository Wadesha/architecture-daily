二、核心建议：双向分流（不是把什么都塞进去）

古村落写作工程有两类不同的"知识"，在 ima 里应该分文件夹、用不同方式存，混在一起会乱：

知识类型例子存哪方式为什么
A. 外部素材（元宝/公众号挖来的原文、转载链接）山亭石板房各篇、营造三普数据ima「淮海素材」文件夹import_urls（存 URL）或把文字粘成 mdima 擅长收藏检索原文；留 media_id 便于日后回源
B. 我们产出的工作文档（scope/联动手册/模仿稿 HTML）淮海_scope、各模仿稿本地工作区为主（C:…/淮海_古村落田野体_scope）本地 + 定期快照存 ima活文档需高频改，ima 不适合当编辑区；当"备份/发布"用
C. 志书/古籍 L1滕县志、铜山县志ima 共享方志库（已有）只读引用不动它，通过 search 定向取料
一句话：ima = A 素材的收纳库 + C 志书的检索库 + B 的只读备份；真正的"编辑战场"仍是本地工作区。别把正在改的 HTML 塞进 ima 当编辑器。

三、最佳实践步骤（怎么跑通整个循环）

① 建文件夹（需你在 ima 客户端做一次）：在个人库 momo的知识库 里新建两个文件夹「淮海素材」和「古村落写作备份」。ima MCP 暂不提供"建文件夹"工具，这一步需手动（约 10 秒）。

② 外采入库：元宝/公众号挖到可用链接 → 你在对话里发我 URL 列表 → 我用 import_urls 存进「淮海素材」，拿到 media_id 回填进 scope 的素材表。

③ 关键原文留档：若某篇原文是纯微信（无公开 URL），你把正文贴给我 → 我整理成 .md → create_media 上传，存「淮海素材」（这样连原生微信内容也能沉淀）。

④ 工作产物快照：每完成一篇模仿稿/一轮 scope 更新，我把 HTML 用 create_media 传一份到「古村落写作备份」，标题带日期。本地仍是最新版，ima 是历史快照。

⑤ 检索回源：写某村前，先在「淮海素材」search_knowledge 把该村材料捞齐，再查共享方志库补史实，最后本地动笔。

四、我这边的工具边界（诚实说明）

  • import_urls（已验证）：能存公开网页链接。
  • create_media 上传本地文件（能力存在，未全链路实测）：需要拿 COS 凭证再传，多一步，第一次要试通。
  • 建文件夹：ima MCP 暂无此工具，需你在 ima 客户端手动建（然后告诉我 folder_id，我就能精准写）。
  • search 返回整篇超限：搜大型 PDF 会超限，需换小 query 或按文档定向读（见联动手册）。

六、本地↔ima 上传状态核查与标记（2026-09-06 实测补充）

问题：「很多内容已经传过 ima 了，到底哪些传过、哪些没有？」——靠记忆或逐个库翻是不可靠的，必须做一次机器核查并留本地标记。

1. 核查做法（脚本化，30 秒出结果）

  • 数据源：本地 zlibrary 书籍文件 ↔ ima 全库条目快照 kb_data/*.json（132 库 / 2200+ 条目标题）。
  • 匹配规则三级：精确（规范化后完全一致）→ 包含（一方包含另一方且 ≥8 字）→ 模糊（相似度 ≥0.72）。
  • 规范化必须做：去扩展名、去 (Z-Library) / [OCR] 标记、去括号内容与标点、去条目前导编号（如 031）与尾部 _0。
  • 脚本：check_local_uploads.py（可重跑刷新）；补传规划 plan_backfill.py。

2. 实测结论（重要，反直觉）

zlibrary 根目录 599 本书，只有 9 本能在 ima 里找到同名条目（约 1.5%）。ima 现有 2183 条主要来自网页/公众号/志书 PDF/其他目录，不是从本地这批书传的。
→ 补传不是"补齐漏传"，而是一次新的入库决策：25 GB / 590 本，全传性价比低，应按主题分批。

3. 踩到的坑（下次直接绕开）

  • 快照会截断：kb_data 里 3 个库（古建筑 45 / 地质地理 34 / 医学教科书 119）各只存了 1 条 → 匹配前必须查 truncated 标记。修法：优先用本地 kb_deep/<id>/_manifest.json 补全；没有的再走 MCP live 拉。
  • 文件在子文件夹里：MCP get_knowledge_list 首层只返回 folder 条目，需拿 folder_id 二次调用。
  • 大库别直接 MCP 全量拉：119 条的库会返回每条完整 introduction，瞬间爆上下文（本次靠本地 manifest 回避）。
  • 不要用改名做标记：OneDrive 同步目录改名常被文件锁拒绝；标记用清单文件（CSV/HTML）而非文件名前缀。
  • 快照会过期（2026-09-07 复核发现）：kb_catalog 139 库 vs kb_data 只有 132 个文件 → 7 个库（253 条）根本不在匹配基数里；且线上条目数已变（地名 5→21、村落田野调查 4→11、古建筑风格工程成品 0→10、山河淮海文案 36→112）。每次核查前必须重拉一次库清单核对条目数，别信旧快照。
  • 纯标题匹配会系统性漏判：改名上传的书按标题匹配必然漏。实测——在古建筑库搜「中国建筑史」命中多个条目（梁思成中国建筑史、图说中国建筑史、中国古代建筑史…），其文件名与本地书名都不一致。标题匹配只能给出"确定已传"的下界，不能给出"确定没传"的结论；要可靠需补一轮内容级检索（按主题到候选库搜关键词）。
  • 扫描范围必须写明：根目录 599 本 + 子目录 205 本 = 804 本；P14 的 work/ 下约 1200 个 OCR 中间产物已排除（不是书）。报告不写清范围与排除规则，数字无从判断。

5. 与既有流程的衔接

第二节「双向分流」不变：外部素材 → import_urls 进「淮海素材库」；本地工作产物 → 定期快照进「古村落写作备份库」。本次新增的是第三条支线：本地存量书籍 → 先核查标记 → 再按主题分批入库，且入库前必须先出分组规划给用户评审（25 GB 量级不可闷头全传）。
